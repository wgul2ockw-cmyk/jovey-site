Jovey · Yeast Lab

พาข้อมูลจากบอร์ดขึ้น Jovey

ESP32 → ส่ง HTTPS ทุก 10 วินาที → Supabase เก็บข้อมูล → Jovey แสดงกราฟและ baseline

ตอนนี้หน้าเว็บพร้อม แต่ต้องเชื่อมฐานข้อมูลและบอร์ดของคุณก่อน

การเปิดหน้านี้ยังไม่ทำให้บอร์ดส่งข้อมูลเอง ไม่มีจุดจำลอง ข้อมูลจริงจะเริ่มเมื่อ Serial แสดง # CLOUD_ACK และจุดบนหน้าเว็บเดินต่อ

ดาวน์โหลด Arduino + SQL + คู่มือ

1 · สร้างที่เก็บข้อมูล

  1. เปิด Supabase Dashboard และสร้างโปรเจกต์ในบัญชีของคุณ เลือกแผนให้เหมาะกับการใช้งานและตรวจโควตาก่อนเริ่ม
  2. แตก ZIP เปิด schema.sql คัดลอกทั้งหมดไป SQL Editor → New query → Run ในโปรเจกต์ใหม่
  3. ไป Authentication → Users → Add user สร้างผู้ใช้ email/password สำหรับเข้าดูข้อมูล บัญชีนี้แยกจากบัญชี Dashboard และต้องยืนยันอีเมลตามการตั้งค่าของโปรเจกต์
  4. คัดลอก User ID เปิด register_device.sql แทน OWNER_UUID ด้วยค่านั้น แล้วรันหนึ่งครั้ง เก็บ device_id และ device_token ที่ได้ไว้เป็นส่วนตัว
  5. หา Project URL และ publishable key (หรือ legacy anon key) จากหน้า Connect / Settings ห้ามใช้ secret หรือ service_role key บนเว็บหรือบอร์ด

2 · เชื่อมหน้าเว็บ

เปิด Yeast Lab ใส่ Project URL, public key และ email/password ที่สร้างในข้อ 1 จะเห็นอุปกรณ์ Yeast bench 01 สถานะ “รอข้อมูล” เป็นปกติจนกว่าบอร์ดส่งเข้ามา URL และ public key จะจำไว้ในเบราว์เซอร์ แต่รหัสผ่านและ session ไม่บันทึกลง localStorage

3 · ใส่ค่าลง Arduino

  1. สำรอง sketch เดิม แล้วเปิด Yeast_Cloud/Yeast_Cloud.ino ใน Arduino IDE ให้มีแท็บ CloudSender.h และ secrets.h อยู่ด้วย
  2. ใช้ ESP32 Dev Module และไลบรารี OneWire / DallasTemperature ตามเดิม ชุดนี้ตั้ง DS18B20 = G4, MQ3 = G34, MQ135 = G35 โดย MQ แต่ละตัวต้องผ่านตัวแบ่งแรงดัน 10K/10K ตามวงจรเดิม
  3. ใน secrets.h ใส่ Wi-Fi, Project URL, public key, device_id และ device_token เครือข่ายต้องออกอินเทอร์เน็ตได้ โค้ดนี้ยังล็อกอินหน้า captive portal ให้อัตโนมัติไม่ได้
  4. เตรียมใบรับรอง HTTPS: เปิด Terminal ในโฟลเดอร์ที่แตก ZIP และรันคำสั่งนี้ โดยเปลี่ยน URL เป็นโปรเจกต์จริง:
python3 prepare_tls.py https://YOUR_PROJECT.supabase.co

ต้องมี Python 3, OpenSSL และอินเทอร์เน็ต โปรแกรมจะตรวจใบรับรองแล้วเติม ROOT_CA ใน secrets.h หากตรวจไม่ผ่านให้แก้ตามคู่มือ ไม่ปิดการตรวจ TLS

  1. เปลี่ยน CLOUD_ENABLED เป็น true แล้ว Upload เปิด Serial Monitor ที่ 115200

ห้ามส่งรหัสผ่านหรือ device_token ในแชตหรืออัปโหลดไฟล์ secrets.h ที่กรอกจริงแล้วเข้า GitHub

4 · ตรวจข้อมูล แล้วเก็บ baseline

  1. Serial ต้องแสดง # CLOUD_ACK points=... และตาราง yeast_samples มีแถวเพิ่ม หากมีแค่ IP ยังไม่ได้ยืนยันการส่งขึ้นเซิร์ฟเวอร์
  2. กลับ Yeast Lab รอสถานะ LIVE และกราฟอุณหภูมิ / MQ3 / MQ135 ขยับ
  3. หลังอุ่นเซนเซอร์และจัดสภาพอ้างอิงให้คงที่ ตั้งชื่อ baseline ติ๊กยืนยัน แล้วกด “เริ่มเก็บ 5 นาที”
  4. รอครบเวลา ระบบใช้ median จากจุดที่เข้าเกณฑ์เพื่อแสดงส่วนต่างของสัญญาณ เลือก baseline เก่าหรือดาวน์โหลด CSV ได้
  5. ทดลองปิดเว็บหนึ่งนาทีแล้วเปิดใหม่ ข้อมูลที่ Supabase รับสำเร็จต้องยังอยู่ บอร์ดยังต้องมีไฟและอินเทอร์เน็ต
อ่านตัวเลขให้ถูก

MQ3 / MQ135 เป็น raw ADC ไม่ใช่ CO₂ หรือความเข้มข้นเอทานอล เกณฑ์ baseline ตรวจความครบของข้อมูล ไม่ได้ยืนยันการอุ่นเซนเซอร์ การสอบเทียบ หรือเวลา harvest เว็บแสดงล่าสุดไม่เกิน 600 จุด ส่วนประวัติทั้งหมดอยู่ใน Supabase

คิวรอส่งบนบอร์ดอยู่ใน RAM และหายเมื่อไฟดับ ยังไม่ใช่เครื่องบันทึกแบบ offline ถาวร
